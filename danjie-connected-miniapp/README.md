# 服装店 自用记账 + 开小票（Phase 1 简化进销存）

原生微信小程序 + 微信云开发（云数据库 + 云函数）。单店、单老板，按 openid 数据隔离。
不接微信支付、不接税务发票、不用第三方框架与 UI 库。

---

## 🚀 5 步部署清单

> 部署前请通读；其中第 3~5 步需要联网 + 微信开发者工具。

1. **注册小程序并拿到 AppID**
   微信公众平台（https://mp.weixin.qq.com）注册**个体户主体**小程序（需营业执照）。
   注册后进入「开发 → 开发管理 → 开发设置」复制 **AppID**。
   > 使用「测试号」或 `touristappid` 无法开通云开发，**必须用正式 AppID**。

2. **安装微信开发者工具**
   下载地址 https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
   （稳定版即可），用你注册小程序的管理员微信扫码登录。

3. **导入本项目并填写 AppID**
   开发者工具 → 导入项目 → 目录选本文件夹根目录 → AppID 填第 1 步复制的值
   （当前 `project.config.json` 中已硬编 `wx0ea32c0706ed8c50`，按需替换）。
   导入后如提示基础库版本，选 **≥ 2.33.0**（低版本缺少 offscreen/canvas 2d 相关能力）。

4. **开通云开发并创建环境**
   工具顶部「云开发」按钮 → 开通（按提示选择免费额度套餐即可）→ 创建环境（记下**环境 ID**）。
   打开 `app.js`，把 `CONFIG.envId` 改成你的环境 ID；留空则使用账号默认环境。

5. **创建集合 + 上传云函数（关键！）**
   - 云开发控制台 → 数据库 → 手动创建以下 **7 个集合**，权限全部选 **「仅创建者可读写」**：
     `goods`、`suppliers`、`sales_orders`、`purchase_orders`、`inventory_logs`、`settings`、`customers`
     > 不要在集合里勾选"所有用户可读"。集合必须提前建好，云函数写不存在的集合会报错。
   - 资源管理/云函数面板里，对 `cloudfunctions` 下 8 个目录逐一 **右键 → 上传并部署：云端安装依赖**：
     `login`、`submitSale`、`submitPurchase`、`returnSale`、`stats`、`settleDebt`、`slowMover`、`statement`、`migrateSku`
   - 建议顺手在集合上按 `DATA_MODEL.md` 的"索引建议"建复合索引（数据少也可先不建）。

6. **（可选，已有旧数据）执行迁移脚本**
   - 如果你**之前**已经在用本项目（旧版只有 goods.stock 单字段），云函数部署完成后，**冷启动**小程序首页会自动跑一次 `migrateSku`，把 `stock` 转成 `skus[默认·默认]`，幂等。
   - 想手动跑：云开发控制台 → 云函数 → migrateSku → 测试 → 空参调试，可看到 `{ scanned, migrated, skipped }`。

完成后点「编译」，首页下拉刷新能看到数据即部署成功。首次使用：**设置页先保存一次店名**
（会自动生成 settings 文档），再进商品管理建档（期初库存>0 会生成期初流水），进货走"进货入库"。

## 🔑 数据隔离与一致性设计（重要）

- 每个集合文档都带显式 **`openid`** 字段；云函数一律用 `wxContext.OPENID` 过滤/写入，
  **不信任客户端传入的身份**；集合权限再设「仅创建者可读写」（_openid 兜底）。
- **改库存只走云函数事务**：`submitSale` / `submitPurchase` / `returnSale` 用
  `db.runTransaction` 原子完成「读商品 → 改库存 → 建单 → 写流水」，任一步失败整体回滚。
- 事务内不依赖 `_.inc` 等指令，一律「先读后写绝对值」，配合事务冲突自动重试，避免覆盖。
- 销售单/进货单**明细内嵌在订单文档**（Phase 1 单量小），不做子集合，事务里一次写入。
- 成本口径：进货按 **加权平均** 更新 `costPrice`；销售时把当时成本快照进明细 `cost`，
  毛利 = 应收 − Σ(cost×qty)，已退货整单从统计剔除。

## 🖨 小票打印接线说明（蓝牙）

链路（全部为微信官方文档化 BLE API）：

```
wx.openBluetoothAdapter
  → wx.startBluetoothDevicesDiscovery / wx.onBluetoothDeviceFound   搜索
  → wx.createBLEConnection                                          连接
  → wx.getBLEDeviceServices + wx.getBLEDeviceCharacteristics        找可写特征
  → wx.setBLEMTU (安卓，可选提速) + wx.writeBLECharacteristicValue  分包写指令
```

- **为什么用位图而不是文本指令**：ESC/POS 中文文本需要 GBK 编码，小程序 JS 无内置 GBK
  编码器；改为把小票用同一份 canvas 排版画成 **384px 宽**位图（58mm @203dpi 正好 384 点），
  `ctx.getImageData` 取像素 → 阈值转 1bpp → 按 **GS v 0**（`1D 76 30 00 xL xH yL yH`）每 8 点一行发送。
  中文不乱码、所见即所得。代价是数据量大（一张小票约 190 行×57B），BLE 分包发送需数秒。
- **分包大小**：安卓优先 `setBLEMTU(512)`（成功≈480B/包），失败退回 20B/包；
  iOS 固定 180B/包。传输中若大包失败自动退回 20B 重试。
- **找特征**：遍历服务/特征，选择支持 `write`(0x08) 或 `writeWithoutResponse`(0x04) 的特征，
  优先无应答模式（快），UUID 含 FFE1（佳博/芯烨常见约定）者加分。
- 打印流程完成后自动 `ESC d 04`（走纸）+ `GS V 65 0`（切纸，无刀机型自动忽略）。
- **注意**：只有支持 **BLE** 的机型可连（佳博/芯烨近年 58mm 多数支持）；老款仅经典蓝牙
  （SPP）的机器微信官方 API 无法连接，属预期内限制。
- 真机验证提示：连接后在打印机页面先点「**打印测试页**」；有图案无乱码再打正式小票。

## 已知限制（Phase 2 候选）

- 仅**整单退货**，不支持部分退货/退部分数量（数据结构已支持行级，后续加 UI 即可）。
- **进货退货**未做；进货单仅查询展示。
- 退货不追溯回退成本价（成本是动态加权平均，历史销售成本不重算）。
- 商品删除限制：库存必须为 0；被删商品的退货会失败（先恢复商品再退）。
- 期初库存建档产生的 `inventory_logs` 由客户端写入（非事务、尽力而为），失败只告警不阻断。
- 单店铺模型：不区分店员/老板权限；数据仅按 openid 隔离。
- 无数据导出/备份界面（云开发控制台可手动导出集合）。
- 客户端列表分页单次 20 条（官方限制），大量历史单据建议收窄日期范围。
- 小票二维码为"占位框"（设置开关），真实收款码/公众号码建议 Phase 2 用图片方式合成。
- 无条码唯一性校验（重复条码时搜索返回多条，点选即可）。
- 客户档案删除保护：客户名下有任意消费/欠款记录不允许删除；销售单上的 customerName/customerPhone 在选客户档案前手填的两份并存。

- 全部代码仅使用微信官方文档化 API；不确定处已在代码注释与 README 中标注待真机验证。

- 日期查询由客户端把本地日期区间换算成毫秒传入云函数，规避云函数时区问题。
